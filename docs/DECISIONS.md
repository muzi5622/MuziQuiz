# Decisions

## Phase 6 — timing, publication and local motion

- Question reading time uses the existing QUESTION_OPEN state with a persisted future options-release/answer-start timestamp. The server withholds options and rejects early guesses. One timer handles release and the inclusive deadline; no tick writes or scoring changes.
- A single tap sends the strictly validated answer; a synchronous in-flight guard prevents repeat UI sends. The server remains authoritative and idempotent. Receipts show server response time immediately.
- Per the user's explicit refinement, answer reveal and score publication are separate. QUESTION_REVEAL can advance directly or publish standings. Pending totals/ranks/history stay sealed; finish closes/reveals the current answering round and publishes final totals. Migration 7 persists publication and the previous ranking snapshot.
- Leaderboards count from previous published totals, then move rows into position using CSS transforms. Published snapshots supply movement for reconnects and players outside the top ten. Motion is local React/CSS, respects reduced-motion preferences, and does not delay server transitions. A dark host control desk prioritizes stage/actions over room details; participant/projector surfaces retain paper/lime styling. No reference artwork or new dependency was used.
- Graceful Socket.IO namespace shutdown requires an explicit client reconnect; transport loss already retries automatically. Removal/host revocation cancel the extra retry. Windows launch and offline audits remain local.
- Load tests use isolated temporary databases and independent server processes with real HTTP/socket requests and production limits. Report measured loopback results separately from unverified physical Wi-Fi capacity.

## Phase 1 — foundation

- One production Fastify HTTP server owns API, Socket.IO and compiled Vite assets on port 3000. No Vite event-day process or internet assets.
- SQLite uses WAL, foreign keys, a busy timeout and transactional versioned migration metadata. Product tables will arrive in their owning phases, avoiding premature schema/security promises.
- Host and participant routes are explicit public placeholders. No passwords, participant data or control events exist yet. Host authentication must precede privileged operations in Phase 2; host sockets require authorization in Phase 3.
- Socket handshakes reject cross-origin browser requests; same-origin local HTTP is supported. This is not host authentication. The app is intended for a trusted isolated LAN.
- Original paper/ink/lime visual direction uses a ticket motif, system fonts, touch-sized links and a persistent connection status. No component inspiration service or external artwork was needed.
- Node 22.13+ supports the environment-file startup flag; Node 24 is the development runtime. Lockfile pins installed dependencies for repeatability. Native SQLite must be installed for the target platform during initial setup.
- Automated same-machine smoke testing cannot establish another-device LAN reachability, offline physical acceptance or 200-client capacity. Those claims remain gated on actual testing.

## Phase 2 — host authoring

- No new runtime dependencies. Node's asynchronous scrypt and crypto randomness implement local password hashing and opaque sessions. Only a terminal command can configure/reset the password; there is no default or remote bootstrap path.
- SQLite migration 2 adds host credentials, hashed sessions, quizzes and ordered questions. Transactions save the full question set atomically; foreign-key cascade deletes questions with a quiz. Replacing question rows is appropriate before live sessions; Phase 3 must snapshot question sets before gameplay and protect active sessions from edits.
- All host APIs are behind session checks except auth status/login. Host API origin checks reject cross-origin requests and require a matching Origin on mutations; responses use no-store. HttpOnly SameSite=Strict cookies work over the specified trusted-LAN HTTP deployment and expire in 12 hours. Their bearer values are stored as hashes, and a password reset invalidates all sessions. No privileged socket events exist yet.
- Login attempts use bounded in-memory per-IP/global windows; these reset with the process. Eight attempts/IP/15 minutes is adequate for a solo operator, with 200 global attempts/15 minutes limiting work on async scrypt.
- Strict versioned Zod schemas are shared across the API and browser. Limits: 100 questions, 512 KiB compact versioned JSON, 1–10,000 base points. Empty quiz drafts are allowed. Unscored polls are intentionally deferred to Phase 5; only quiz_mcq is accepted by Phase 2 contracts.
- Valid edits autosave after 800 ms. A monotonically increasing updated_at value doubles as an optimistic concurrency revision; stale writes return 409 instead of overwriting another tab. Invalid/failed edits remain in memory with a warning and explicit retry; they are not claimed durable until acknowledged.
- Original paper/ink/lime styling extends into an indexed quiz library and question cards. System fonts and compiled local assets remain the only visual dependencies. No targeted external inspiration was used.

## Phase 3 — live lobby

- Migration 3 adds sessions, immutable session-question copies, participants and indexes. A partial unique index allows only one unfinished session; six-digit PINs are unique across stored history, preventing old URLs/tokens from accidentally attaching to a new session. Snapshot records survive deletion of the original quiz, so sessions deliberately keep the source quiz ID without a deleting foreign key.
- Host creation requires at least one saved question and an explicitly selected current numeric IPv4 adapter. The join URL uses the actual HTTP port. Address choice persists with the session; the operator still verifies reachability and firewall/AP configuration.
- `qrcode` is the only added runtime dependency and generates PNGs locally on the server. Host/projector load these from the same origin. No QR service, remote asset, DNS or browser Secure Context API is required.
- Socket namespaces separate `/host`, `/participant` and `/present`. Host handshakes verify cookie and browser origin evidence; polling may use same-origin Fetch Metadata when browsers omit Origin. Every host action rechecks authorization and validates a strict shared schema. Broadcasts recheck host sessions before disclosing rosters; idle revoked sockets are retired within 10 seconds. Root/participant/projector sockets have no host handlers.
- The HttpOnly SameSite=Strict cookie now uses Path=/ to reach Socket.IO. Login/logout also expire the legacy Phase 2 narrow-path cookie. The cookie remains HTTP-compatible for the required isolated LAN; no admin bearer value is exposed to client JS.
- Host UI sockets use a fresh transport after login so they do not reuse a public status connection whose original handshake predates the authenticated cookie.
- A participant token is 32 cryptographically random bytes. Only SHA-256 hashes persist; raw tokens stay in the participant browser and socket handshake, never public snapshots or URLs. NFKC nickname normalization plus case-normalized unique keys and deterministic suffixes prevent duplicate display identities, including removed names.
- Connected presence uses an in-memory set of socket IDs per participant, not a socket count. It is reset at restart; identities persist. Last-seen writes occur on connection/disconnection only. State-change broadcasts coalesce for 75 ms; there are no per-second database/broadcast ticks. Shutdown disconnects all namespaces before closing SQLite.
- End-lobby and removal actions are idempotent. Removal revokes an identity rather than banning a physical device. A 200-identity/session admission cap includes removed entries to bound churn, not to claim measured capacity. Fixed-window IP/global limits bound join, handshake, reconnect and host-command abuse; counters reset at process restart. Public PINs do not constitute private-room authentication; the deployment assumes a trusted isolated LAN.
- Phase 3 restores lobby identity and a zero score; actual scoring, question state/delivery and accepted submissions belong to Phase 4. Public and participant lobby payloads contain no question/options/correct-answer data or other players' private information. The projector shows aggregate counts, not a public nickname roster.

## Phase 4 — timed questions and immutable answers

- Migration 4 adds question runtime timestamps, host transition revision, latest disconnect metadata and submissions. Composite foreign keys enforce participant/question session membership; a unique key and update/delete-denial triggers preserve accepted submissions. Transactional aggregate queries supply score totals, with no mutable client-provided total.
- A dedicated QuizEngine owns state, clock, deadlines and scoring. Production uses Date.now for both start and immediate socket receipt. Test-only constructor clock injection permits deterministic exact-boundary and restart tests; no request/environment setting can supply a clock or score.
- QUESTION_OPEN plus a persisted closed_at flag represents closed/waiting-for-reveal. Expiry closes at end+1 ms, preserving exact-deadline eligibility. It never reveals or advances. Early close does not shorten the original scoring duration. Startup restores timestamps and permanently closes expired questions.
- Only authenticated host actions start, close, reveal, continue and advance. Expected server revisions stop duplicate/stale actions from skipping questions. LEADERBOARD is a between-round stage until Phase 5 ranking UI; no automatic next-question behavior exists. Finish is terminal/idempotent and does not reveal an unrevealed question.
- The participant submission schema contains only questionId/optionId. Identity derives from the validated token, and all authorization/session/question/option checks precede an explicit-column SQL insert. Strict schemas reject unknown/nested mass-assignment fields; Fastify rejects prototype/constructor poisoning. No-field HTTP controls reject nonempty bodies, and projector/host socket auth payloads are strict too.
- Existing submissions are returned on authenticated retries even after closure/advance. Points are computed once on the server and remain immutable. Before reveal, receipts omit awarded points/correctness and personal totals exclude unrevealed questions, avoiding an indirect correctness leak. Only that identity receives its private state; shared progress carries counts and host answered flags.
- Updated private state is coalesced in 75 ms batches and sent per identity (once computed for multiple tabs). One deadline timer is armed for the active question; no per-tick DB writes or broadcasts. UI timers use a round-trip server clock offset and remain cosmetic. Answers are limited to 30 attempts/identity/minute, 1,200/IP/minute and 6,000 globally/minute.
- Latest disconnect timestamp/reason persists independently of immutable answers. Removing an identity does not void/delete an already accepted submission. Re-runs/voids remain outside this phase.
- Existing same-browser tokens resume throughout the game; new identities join only in the lobby. Refresh/reconnect restores stage, original deadline, accepted choice and revealed-question score. The original paper/ink/lime interface extends to answer cards, explicit receipts, countdowns and reveal charts without additional dependencies.

## Phase 5 — standings, polls, exports and character lobby

- The user's explicit additions restrict nickname input to letters/numbers on both client/server and add automatically assigned character arrivals. Invalid symbols/whitespace are rejected, not silently stripped. Numeric suffixes remain alphanumeric, with Unicode-safe truncation. Migration 5 normalizes legacy displays while preserving IDs/tokens/answers.
- A server-assigned avatar index persists per identity and is unique within a session, including removed identities. Twenty-four local Unicode animals and ten background colors supply distinct combinations for 200 identities. The projector shows latest 48 arrivals; the participant lobby shows 12; the host retains all. Names/icons are intentionally public in the lobby per the user's request; private answers remain protected. No external icon/font asset or cloned third-party artwork is used.
- Rankings use revealed scored answers only: score descending, correct count descending, cumulative valid response_ms ascending. Polls cannot affect any tie-break metric. Exact ties share competition rank; joined-at/id controls stable display order. Public standings are top ten between rounds/at finish; podium is first three identities at finish. Poll-only sessions have no ranked podium. Ranking maps are computed once per broadcast batch rather than once per participant.
- Polls have null correct choice and zero maximum/awarded points; migration 5 rebuilds the authoring question constraint to enforce this. Polls use the existing deadline/immutable-answer engine, reveal counts/percentages on host action, and never label a vote as incorrect. Scored MCQs keep mandatory speed scoring.
- CSV exports explicitly select safe data fields and quote every cell, double embedded quotes, preserve line breaks and neutralize formula prefixes even after leading whitespace/control bytes. UTF-8 BOM improves Windows spreadsheet decoding. Host authentication/origin checks protect participant and question-statistics downloads; no bearer/credential fields are serialized.
- Recent finished sessions expose the latest 20 host-only summaries so organizers can reopen results/export pages. No new runtime dependencies were added.

## Authoring follow-up

- The import guide is a native accessible modal with schema-valid example JSON and a read-only, copyable external-tool prompt. Clipboard fallback selects the prompt for manual copying on plain HTTP LAN origins. File-size/schema limits and host authorization remain unchanged; no AI integration or dependency was introduced.
- Explicit saving shares the autosave operation and a synchronous in-flight guard. The sticky bar distinguishes pending/invalid/saving/saved states and confirms the number of saved questions.
- The orphan room was caused by independent session snapshots outliving saved-quiz deletion, plus a mount-only active-room query. Quiz deletion now ends only the matching active session transactionally before deleting the authoring data. Session results/immutable answers survive. Library refresh after quiz changes and on window focus removes stale room banners. Regression tests exercise deletion during answering, unrelated deletion, unauthorized/forged requests, preserved results, restart and opening a replacement room.
- Active-room lookup also finishes legacy rooms whose saved quiz is already missing, preserving their results and recovering the blocked session slot. This repairs existing installations without deleting their event history.

- Added file/paste choices to the existing import dialog. Both call one shared text parser before the existing host-only endpoint. UTF-8 byte limits are checked before JSON parsing; schema errors include the field path. An in-flight guard prevents duplicate import requests. No dependency or server contract changed.

- Recent finished sessions lazily load their saved final standings through the existing authenticated session endpoint; no extra copy of scores or schema migration is needed. Ranking derives from persisted published submissions and session snapshots, so quiz deletion does not remove results. A regression test verifies exact final rankings after quiz deletion/restart and denies anonymous access. The library Duplicate action was removed as requested.

- The provided Mentimeter reference images informed only the large-choice-card and count-above-bar interaction patterns. LocalMenti keeps original paper/lime typography, palette, layouts and local CSS; reference images are ignored development files and are not shipped as assets. The server-supplied reveal gates every distribution and correctness popup. The existing persisted options-release timestamp remains the answer/scoring start, so the visual redesign does not alter deadlines, speed scoring or request authority. Polls never receive correctness feedback; missing submissions receive a neutral notice. Native dialog feedback is keyboard-dismissible and reduced-motion styles disable entry/bar animation. Points and rankings retain their separate host publication gate.

- Quiz-wide timing replaces per-question authoring duration. Migration 8 stores quizzes.duration_seconds, chooses the first saved question duration (or 20), and normalizes authoring rows. Runtime session snapshots remain untouched, preserving existing deadlines and scoring. New sessions use the one quiz duration for every scored question and poll. JSON v2 makes the global field explicit; legacy v1 imports convert deterministically using the first question and strip old overrides. No scoring-mode change or new dependency.

- The disabled clean-state Save button made already-persisted imported quizzes appear unsaveable. Explicit Save quiz & return now works for clean and dirty valid drafts, returns only on success, and checks that no newer edit appeared during the request. Import completion explicitly confirms persistence.
- Session creation stays on the library and exposes a separate lobby link. The host Next reveal action performs close and reveal as two authenticated revision-checked commands; a failed close aborts the chain. Host-selected leaderboard publication remains separate. The retired version-1 JSON importer was removed; durable migrations and saved event history are retained.

- Added happy-dom as a development-only dependency for actual React button/event regression tests. Tests exercise paste and file import, clean and dirty explicit saves, failed-save navigation protection, creating a session without redirect, and opening QR/PIN before manually starting question one. HTTP/socket responses are controlled test doubles; existing server integration tests exercise persistence and authorization separately.

- Fixed the host-control login redirect: Socket.IO default polling GETs on an insecure LAN origin can lack Origin/Fetch Metadata, while the host namespace required origin proof. The host console now starts a fresh credentialed WebSocket transport, whose browser handshake carries Origin, without relaxing the server gate. Origin failures and missing credentials now have distinct errors. The host screen loads over authenticated HTTP independently, and checks HTTP auth before treating socket rejection as sign-out.
- Expired-login return navigation is owned by a single authenticated login-route redirect. The previous competing imperative navigation and login-route redirect could return to the library instead of the requested session. React DOM tests reproduce both the socket rejection with a valid login and login renewal returning to QR/PIN controls; real Socket.IO tests verify cookie/Origin authorization and starting the first question.

- Per the latest interface refinement, participant screens no longer render room distributions, top-ten lists, podiums or history. Their private socket projection removes global option counts/player lists/standings, while keeping their personal rank and points and the host-revealed correct choice. Host snapshots include previously published rankings during later questions so the side panel survives refresh without publishing current scores early.
- Host desktop controls use a split question/action and leaderboard panel. Colored horizontal score fills, counted totals and transformed rank rows use the existing server publication baseline and reduced-motion behavior. The participant shell hides global chrome, uses safe-area/dynamic-viewport sizing and compact touch choices, and replaces choices with the personal receipt after one tap. Extremely long text may overflow so no answer is silently clipped. Native feedback is dark green with high-contrast lime/warm result colors. No reference artwork, animation library or runtime dependency was added.

- Consolidated the host console into /present/:pin. The projector checks existing cookie authentication, resolves the session from its public PIN and renders the same authenticated host socket controls for hosts; other viewers retain the read-only presenter. Old host-session links are redirect-only and library links now point directly to the projector. Login return destinations permit internal projector PIN routes. No host secret is embedded in a URL or the bundle.
- The live host projector keeps QR/PIN, question/reveal/Next and animated standings, dropping management details and intermediate downloads. One all-player CSV link appears after FINISHED. The existing protected export already covers all participants, including rows beyond the top-ten board; a 12-player regression verifies this.

- Replaced the static waiting QR block with a shared viewport-aware welcome lobby for host and read-only projectors. It shows a bounded recent-avatar gallery (6/12/24 by viewport), stable keyed zoom-in arrivals, and connected identities at bottom-right. Joined/disconnected counts remain distinct; multi-tab sockets do not inflate the live counter. No per-tick broadcasts/writes or external event dependencies.
- Added 50 special emoji/color variants after the original 240 indices, preserving existing avatar mappings. New joins choose uniformly from unused indices using server cryptographic randomness, persist the result and reserve removed identities' variants as before.
- Normal heading tracking fixes crowded desktop lettering. Live panels fit dynamic viewport bounds, with scroll as a safeguard inside unusually long content; small host screens switch between Question and Leaderboard while retaining actions. Recent history uses native collapsed details plus a bounded expanded list.
- Added a strictly validated, same-origin authenticated HTTP Stop session action for the library, reusing the idempotent server engine. Host projector Stop retains authenticated socket control. Both preserve final results and free the active session slot.

- Replaced the legacy host-session DOM wrapper, split panels and stacked metadata with a single presentation-screen namespace and surface. It avoids inherited green/light card styling and uses one consistent high-contrast slate/gold presentation palette. Leaderboard publication changes the same surface from question to standings; actions remain in a fixed layout row. Join IP/port has a prominent headline and QR/PIN remain available.
- The saved-token join shortcut previously still encountered required nickname validation. It now hides that field for a recognized saved PIN and resumes without creating another identity. Existing server reconnect behavior was verified across three missed rounds: accepted points persist, missing rounds contribute zero, and the current fourth question retains its original scoring start/deadline. No new mid-session identities or client-supplied scores/times are allowed.


## Reserved participant identity

MUZI (case-insensitive, including compatible Unicode forms) is reserved across events. Ordinary entries of that name receive a generated Player name. A private join code is the sole exception to the letters/numbers-only join input rule; the server verifies its SHA-256 hash from RESERVED_JOIN_CODE_HASH. The accepted identity displays MUZI with an exclusive skull avatar and gold callout. The code is never a host credential and grants no scoring advantage. Only one reserved identity can join each session; its reconnect token restores it. Ordinary names and avatar/color combinations remain unique within the 200-player limit. Migration renames legacy unverified MUZI entries while retaining IDs, reconnect hashes, answers and points.


## Leaderboard graph and recognition

Host/projector standings hold the prior published points briefly, animate score totals, gains and proportional graph bars together, pause, then move rows into their new rank order. Refresh does not replay an already seen revision, and reduced motion displays final values immediately. The Fastest badge recognizes the lowest average server-measured correct-answer time across all published scored questions; exact ties share it. Polls, wrong answers and pending rounds are excluded. Players with no correct answers cannot receive it. The reserved MUZI identity carries a short Creator badge on the leaderboard with no score or rank advantage. Participant screens continue to show only their own rank and published points.


Leaderboard follow-up: score growth uses a distinct bright graph track and a slower 2600 ms count-up before rank movement. A reveal is remembered only after completion, so interrupted mounting cannot suppress the animation. Replay reveal replays the published score change without publishing new information; reduced-motion settings still apply. Fastest is now a competition-wide correct-answer average, displayed with an avg label, rather than a single-question award.


## Import copying, finished-data reset and presentation motion

The JSON structure disclosure starts collapsed. Copy AI prompt copies only the quiz-writing/conversion prompt; insecure LAN HTTP uses a selected-text copy fallback, with explicit manual-copy feedback if the browser refuses. Host-only Reset finished-session data confirms the action and first backs up SQLite locally, then transactionally removes only FINISHED sessions and their participants, snapshots and submissions. Saved quizzes, credentials and active sessions remain. Migration 10 permits submission deletion only for finished events to support this explicit reset; live answers remain immutable and all answer updates remain blocked. Presentation row spacing inherits its viewport size rather than a fixed 85px override. Full-height colored score graph bars grow with point counting after a short delay, then rows move with native Web Animations (CSS fallback), without external assets. Reduced motion and published-score privacy remain in effect.

The public product name is MuziQuiz. Existing @localmenti workspace scopes, database filenames and browser storage keys are retained for backwards compatibility.
